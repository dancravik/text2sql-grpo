# Воспроизведение

## Доказательные файлы и графики

Из корня клонированного репозитория, Python 3.13:

```bash
python -m pip install "matplotlib==3.11.1"
python scripts/build_results.py
```

Построение использует `results/published` и `splits/v1.json`.
`provenance.json` содержит путь к исходному локальному артефакту и SHA256
каждого опубликованного доказательного файла. Исходные пути документируют
происхождение; для построения достаточно копий внутри published.

Для каждой оценки проверяются manifest, 956 уникальных ID, одинаковый текст
вопросов, базы и эталоны, один greedy-ответ, настройки генерации и соответствие
метрик сохранённым исходам. Метрики, полные ответы и история обучения
сохранены без весов, SQLite и API-ключей.
`summary.json` и PNG — производные файлы, их можно пересоздать.

## Данные

Подготовьте `DATA_DIR` с прежними файлами Spider и BIRD:

```text
DATA_DIR/
  spider/
    train_spider.json
    dev.json
    tables.json
    database/<db_id>/<db_id>.sqlite
  minidev/MINIDEV/
    mini_dev_sqlite.json
    dev_databases/<db_id>/<db_id>.sqlite
```

Точную структуру загрузчиков смотрите в `src/data.py`. Manifest хранит SHA256
всех использованных исходных файлов. При отличающемся релизе данных проверка
остановится. Повторно создавать manifest для воспроизведения этих результатов
не требуется.

```bash
export DATA_DIR="/absolute/path/to/data"
python scripts/freeze_splits.py --verify
```

## Среда GPU

Проверенная среда описана в первых ячейках Kaggle-ноутбуков. Использовались
Python 3.13, torch 2.13.0, transformers 5.17.0, peft 0.21.2,
accelerate 1.15.0, trl 1.16.0 и vLLM 0.31.0.
Для успешного запуска на Kaggle также закреплялась версия
`nvidia-cudnn-cu13==9.23.0.39` и удалялись конфликтующие torchao/torchcodec.
[Полный список пакетов успешной sampling-сессии](../results/published/successful_environment.txt)
сохранён для диагностики. Основной способ установки — ячейки ноутбука,
учитывающие CUDA-индексы и порядок установки cuDNN.

Для Comet задайте `COMET_API_KEY`, `COMET_WORKSPACE` и
`COMET_PROJECT_NAME` через Kaggle Secrets или локальное окружение.
Исходный ключ не публикуется. ID эксперимента в отчётах используется
для привязки оценки к истории обучения.

## Основные модели

Скрипты поддерживают загрузку адаптеров из отдельной папки с
`adapter/` и `run.json`. В опубликованных run.json зафиксированы все параметры.
Для выбранных моделей:

| Папка published | Веса |
|---|---|
| `base` | HF-модель Qwen/Qwen3.5-2B с закреплённой ревизией |
| `sft` | Финальный адаптер SFT после 728 шагов |
| `base_grpo` | Финальный адаптер Base → GRPO, LR 1e-5, шаг 128 |
| `sft_grpo` | Обычный отбор SFT → GRPO, LR 2.5e-6, шаг 1024 |

Адаптеры доступны владельцу проекта в Comet и локальных архивах.
Публичной ссылки на скачивание весов в репозитории нет.
Для точного повторения inference нужны эти адаптеры. Для независимого
повторения обучения используйте ноутбуки и те же параметры из run.json.
Совпадение результатов повторного обучения при изменении среды не гарантировано.

Чтобы проверить выбранную модель, сначала слейте адаптер с Base в отдельном
CPU-процессе, затем запускайте vLLM на одной T4:

```bash
CUDA_VISIBLE_DEVICES="" python scripts/export_sft.py \
  --run-dir /absolute/path/to/saved_run \
  --out-dir /absolute/path/to/exported_run

CUDA_VISIBLE_DEVICES=0 python scripts/evaluate.py \
  --model /absolute/path/to/exported_run/merged \
  --datasets validation --name candidate --out-dir results/local_eval \
  --n 1 --temperature 0 --enable-thinking off \
  --max-tokens 1024 --max-model-len 4096 --seed 42
```

Сначала завершите обучение всех параллельных запусков. Затем выполняйте
слияние и оценку последовательно. Это ограничивает нагрузку на RAM и GPU.

## Зарезервированная финальная оценка

Выбранные веса перечислены в предыдущей таблице. Для них можно один раз
запустить `--datasets test_spider test_bird` вместо `validation`.
Для Base используйте HF ID и закреплённую revision.
После оценки всех четырёх веток соберите сравнение:

```bash
python scripts/compare_runs.py \
  --base results/final/base \
  --sft results/final/sft \
  --grpo results/final/base_grpo \
  --sft-grpo results/final/sft_grpo
```

Здесь предполагается, что оценки сохранены в указанных папках. Эта команда
читает готовые файлы и не запускает генерацию. Итоговый test нельзя использовать
для повторного подбора конфигурации. Пока эти оценки не выполнены, таблицы
проекта описывают validation.

## Проверки кода

В среде с зависимостями обучения:

```bash
python -m unittest discover -s tests -q
```

Тесты проверяют разбиения, сравнение, отслеживание шагов, резервные копии,
групповой отбор и восстановление этапов после ошибок. GPU forward/backward
проверяется отдельно первыми ячейками ноутбука.

Контрольные точки GRPO сохраняют веса и отчёты. Состояние оптимизатора для
точного продолжения с середины обучения в них отсутствует. Снимок можно
оценить отдельно, указав фактический шаг.
